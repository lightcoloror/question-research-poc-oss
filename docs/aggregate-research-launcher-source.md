# Aggregate Research Launcher Source Guide

## 1. Purpose and Scope
This document specifies the operational lifecycle and parameter contracts for the Question Research POC (QRP) aggregate research launcher (`scripts/start-ai-aggregate-deep-research.ps1`) under the Apache-2.0 license. The script sequences project staging, provider configuration, orchestration bundle creation, and Web UI serving. No third-party browser automation frameworks, provider credentials, or user session data are distributed.

## 2. Execution Lifecycle and Pipeline Stages
The launcher executes five sequential stages:
- **[1/5] Project Initialization**: Evaluates `$Project` (defaulting to `config/runtime.json`'s `default_root` or `.research-question`). If `research.json` is missing, it executes `init` to scaffold project directories.
- **[2/5] Profile Template Writing**: Executes `write-external-researcher-profile-template` to generate `config/external-researcher-profiles.json`. The backing writer creates a bridge tracking record and renders template files; existing-file merge or preservation guarantees are unverified.
- **[3/5] Orchestration Bundle Generation**: Dispatches `run-omnigent-external-research-poc`. Although termed a dry run by default, this call is intended to create bundles and stage records; dry-run wording is not a no-write or globally offline guarantee. Supplying `-LiveAutomation` passes `--live`, requesting live browser automation that may submit prompts to provider sessions when appropriately authorized; actual provider behavior and connectivity are unverified here.
- **[4/5] Login Preparation**: Enabling `-OpenLoginProfiles` runs `prepare-external-researcher-login-profiles` with `--live` to launch browser sessions for manual provider authentication.
- **[5/5] Web UI Service**: Evaluated after stages 1–4. The `-PrepareOnly` switch exits cleanly here, skipping UI startup while retaining earlier filesystem writes and live interactions. Otherwise, it checks for a local listener on the configured port (public configuration and source fallback use 8775). Only when a listener is found does it probe the configured base URL with HTTP GET /api/agent/manifest. HTTP200 plus the manifest-string check permits reuse; this is not authenticated service identity, PID ownership, schema or account verification. A nonmatching listener causes an error. If the port is free, `run-web` executes in the foreground.

## 3. Parameter Flags and Verification Boundaries
- **Parameter Controls**: Configures 11 parameters covering research questions, sample provider names ("豆包深入研究, 通义千问研究"), timing thresholds (`-FollowupWaitSeconds 10`, `-MaxWaitSeconds 900`), and browser flags (`-NoOpenBrowser`).
- **Verification Status**: All launcher paths remain strictly **UNEXECUTED (NOT RUN)**. Full fixed source, selected public CLI option declarations, the wrapper and exact profile-writer body were inspected. One non-executing Parser.ParseFile check of this exact source on current PowerShell7.5.2 returned zero errors, 11 parameters and 2 functions. It did not invoke this source, a CLI or native argument binding. No runnable quickstart is provided due to default filesystem mutation effects.

The NoOpenBrowser switch controls browser opening in the final WebUI stage only; it does not suppress earlier LiveAutomation or OpenLoginProfiles. PrepareOnly likewise does not roll back or suppress stages1-4. Printed ready/done messages, provider labels and the static configuration are not research completion, current account access or verified evidence. No PowerShell5.1/runtime compatibility, project mutation, actual profile/bundle, browser/login, HTTP/service, provider/model, installation or real-data behavior was tested. The backing template renderer overwrite/merge behavior remains unverified. Public source availability does not authorize those actions.
