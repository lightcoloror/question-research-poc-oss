# QRP Release Portability Regression Test Source Guide

## 1. Purpose and Scope
This document specifies the regression source contracts for the four test methods in `tests/test_release_portability.py` under the Apache-2.0 license. The unchanged source expresses expected environment variable path overrides, per-call tool registry resolution, relative project root anchoring, and packaged schema mirroring for the Question Research POC (QRP) without bundling external runtimes, live credentials, or production databases.

## 2. Four Source Contracts
The four original functions retain the following assertions; these describe expected contracts, not observed passing outcomes:
- **Runtime Path Environment Overrides**: `test_runtime_paths_use_environment_overrides` validates dynamic monkeypatch overrides across five core subsystem roots: workspace, local tool registry, AI research workflow, web content fetcher, and video knowledge pipeline.
- **Dynamic Registry Call-Time Binding**: `test_registry_callers_resolve_environment_override_at_call_time` confirms that health dashboards, dry-run tool-action plans, and web tool payloads resolve the active synthetic registry per call. The `_tools_payload` function is invoked directly in-process without an active HTTP server, and `run_local_tool_action` operates with `execute=False` before any subprocess invocation.
- **Repository-Relative Project Roots**: `test_relative_default_project_root_resolves_from_repository` asserts that relative default project configurations resolve directly against `PROJECT_ROOT`.
- **Packaged Schema Mirror Parity**: `test_packaged_schema_mirror_matches_canonical_schema` asserts strict JSON equivalence, byte-for-byte identity, and fixed SHA-256 matching (`3c2e0e9a05034b1ffa3693735da128c7d3e114ddb155f11668120b974fee1009`) between `schemas/research-output.v1.schema.json` and its packaged mirror under `src/question_research_poc/schemas/`.

- **Harness Environment**: Tests rely on `conftest.py` synthetic fixtures and `offline_only` network socket blocks. Path assertions reflect checkout source trees rather than relocated wheel installations.

No formal case reports were generated: zero original tests ran, all four remain not_run; this is a harness block, not a candidate assertion failure. Full first-error logs were preserved. No retry, guard weakening, readline stub, interpreter/environment replacement, installation or security change was made. No runnable commands are provided.
