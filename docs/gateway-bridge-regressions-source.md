# QRP Model Gateway Bridge Regression Test Source Guide

## 1. Purpose and Scope
This document specifies the regression source contracts for the integration test suite in `tests/test_model_gateway_bridge.py` under the Apache-2.0 license. This increment preserves 19 test functions and 6 helpers declaring contracts between Question Research POC (QRP), AI Research Workflow (ARW), and Model Provider Gateway (MPG). The following groups describe source assertions, not observed execution results. It covers consent enforcement, request-specific receipt binding, fail-closed error handling, and multimodal delegation without bundling model weights, operational API credentials, or private research records.

## 2. Test Architecture and Contract Groups
The 19 test functions partition into five primary contract groups:
- **Candidate-Only Generation and Idempotency**: The source expects candidate-only output fields, unchanged selected truth files and deterministic saved-receipt reuse, with no automatic fallback or silent retry. A declared research_truth_effect:none field is not proof that no mutation occurred.
- **Semantic Versioning and Drift Rejection**: Validates content-hashed ARW semantic contracts, confirming version gates over Git commits while fail-closed parameterizations reject drift across package versions, contract versions, and gateway hashes.
- **Request Binding and Error Transparency**: Asserts expected hash and request-fingerprint binding of receipts and verifies unmasked pass-through of upstream provider errors (HTTP 429 and 500).
- **Multimodal Delegation**: Validates candidate-only vision delegation and owner-receipt embedding flows, enforcing strict embedding dimensionality and rejecting tampering across plan revisions and input hashes.
- **Truth Preservation Boundaries**: The `_assert_truth_unchanged` helper strictly checks exactly three files (`sources.jsonl`, `claims.jsonl`, `evidence.jsonl`), not the broader filesystem. Negative tests verify that mutating delegates are blocked from returning valid candidates, but do not assert automatic filesystem rollback.

## 3. Dependency and Execution Boundaries
- **Module Import Behavior**: The file unconditionally imports `research_workflow` and `model_provider_gateway` at top level; missing packages cause pytest collection failures before skips apply. Nine test functions retain the original @requires_semantic_arw skip marker; that marker is neither dependency readiness nor passing proof.
- **Loopback and Harness Conflict**: The imported model_provider_gateway.mock_server implementation can initiate loopback HTTP listeners on a background thread, conflicting with `offline_only` socket blocks declared in `tests/conftest.py`.
- **Verification Status**: 0 of 19 test functions were executed (**UNEXECUTED / NOT RUN**). The exact fixed Git source hash and prior complete qualified review were reused. Owner verified byte identity, complete AST, original function/helper/marker counts and non-executing compile; public QRP export names were inspected. Module imports, collection, dependency compatibility and runtime behavior were not tested. No runnable commands are supplied.
